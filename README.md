# Royal Club — پنل گزارش کمیسیون

یک نمونه آزمایشی برای مدیریت صرافی‌ها، محصولات، رفرال کدها و گزارش‌های کمیسیون. این پروژه به‌عنوان تمرین برنامه‌نویسی و برای نمایش شیوه دریافت، تطبیق و تحلیل داده‌ها تهیه شده است.

## قابلیت‌ها

- پنل فارسی با Laravel و Filament برای مشاهده صرافی‌ها و بروکرهای از پیش تعریف‌شده و مدیریت محصولات، رفرال کدها و حساب‌های کاربران صرافی‌ها.
- ثبت و نمایش گزارش‌های حجم معاملات و کمیسیون، همراه با فیلتر، تطبیق وضعیت و خروجی اکسل.
- دریافت داده‌های شبیه‌سازی‌شده LBank و Orbit از طریق provider و adapter مستقل.
- تولید فایل اکسل نمونه Bitunix و بارگذاری آن با کنترل ستون‌ها و تبدیل به قالب مشترک گزارش‌ها.
- تطبیق گزارش با حساب کاربر و رفرال کد همان صرافی؛ محصول گزارش از رفرال کد مرتبط تعیین می‌شود.
- دستیار تحلیل گزارش‌ها با پرسش آزاد و پرسش‌های آماده. خلاصه کمیسیون و تعداد حساب‌ها بدون درخواست به مدل محاسبه می‌شوند؛ تحلیل‌های دیگر به سرویس هوش مصنوعی نیاز دارند.
- امکان استفاده اختیاری از فیلترهای جدول گزارش در درخواست‌های چت.

## وضعیت داده‌ها و محدودیت‌ها

- **ارتباط واقعی با API صرافی‌ها پیاده‌سازی نشده است.** داده‌های LBank و Orbit توسط مولد داده آزمایشی ساخته می‌شوند و قالب اکسل Bitunix نیز برای نمایش فرایند ورود و تطبیق طراحی شده است؛ این قالب الزاماً قالب فایل واقعی صرافی نیست.
- ابزارهای تحلیل در داخل برنامه و به شکل function calling پیاده‌سازی شده‌اند؛ پروژه سرور مستقل MCP ارائه نمی‌کند.
- شناسه مشترکی برای اتصال حساب یک فرد در صرافی‌های مختلف وجود ندارد؛ بنابراین آمار حساب‌های صرافی به معنی تعداد افراد یکتا نیست.
- جلوگیری از ثبت تکراری بر اساس ترکیب صرافی، UID، زمان گزارش و حجم معامله انجام می‌شود. در نسخه آزمایشی، برای جلوگیری از خطا با داده‌های نمونه‌ای که ممکن است دقیق یا یکتا نباشند، محدودیت یکتایی پایگاه داده روی گزارش‌ها اضافه نشده است. ایندکس معمولی برای جست‌وجو وجود دارد؛ برای نسخه عملیاتی باید شناسه واقعی رکورد صرافی و محدودیت یکتایی بررسی شوند.
- این نسخه برای محیط آزمایشی است؛ مدیریت کاربران و مجوزها، اعتبارسنجی و تست‌های خودکار پیش از استفاده عملی نیاز به تکمیل دارند.
- تحلیل مدل ممکن است اشتباه باشد و به ارسال داده‌های مرتبط برای ارائه‌دهنده هوش مصنوعی نیاز دارد.

## پیش‌نیازها

- Docker و Docker Compose.
- برای چت مبتنی بر هوش مصنوعی، کلید و سرویس سازگار با OpenAI Chat Completions و قابلیت tool calling.
- Node.js و npm فقط برای ساخت فایل‌های فرانت‌اند در صورت نیاز به صفحه اصلی پروژه.

## راه‌اندازی با Docker

فایل محیط را از نمونه بسازید:

```bash
cp .env.example .env
```

در فایل `.env` تنظیمات پایگاه داده را مطابق سرویس MySQL در `docker-compose.yml` تغییر دهید:

```dotenv
APP_URL=http://localhost:8000
DB_CONNECTION=mysql
DB_HOST=db
DB_PORT=3306
DB_DATABASE=royal_db
DB_USERNAME=root
DB_PASSWORD=root
```

سپس کانتینرها را اجرا و وابستگی‌ها را نصب کنید:

```bash
docker compose up -d --build
docker compose exec app composer install
docker compose exec app php artisan key:generate
```

پس از آماده شدن MySQL، اجرای هر دو دستور زیر ضروری است: migration جدول‌ها را می‌سازد و seeder صرافی‌ها، محصولات، رفرال کدها، حساب‌های آزمایشی صرافی‌ها، گزارش‌های نمونه و حساب ورود به پنل را ایجاد می‌کند:

```bash
docker compose exec app php artisan migrate
docker compose exec app php artisan db:seed
```

اجرای کانتینرها این دو دستور را خودکار اجرا نمی‌کند. اگر MySQL هنوز در حال راه‌اندازی بود، پس از آماده شدن آن دستور migration را دوباره اجرا کنید.

برای ساخت فایل‌های فرانت‌اند صفحه اصلی، در صورت نصب Node.js و npm روی سیستم میزبان، این دستورها را از پوشه پروژه اجرا کنید:

```bash
npm install
npm run build
```

پنل در مسیر `http://127.0.0.1:8000/admin` در دسترس است. داده‌های نمونه و یک حساب آزمایشی توسط `DatabaseSeeder` ساخته می‌شوند:

- ایمیل: `admin@royalclub.test`
- رمز عبور: `12345678`

این حساب فقط برای اجرای محلی و ارزیابی است. اجرای مجدد seeder اصلی رمز همین حساب را دوباره تنظیم می‌کند؛ از آن در محیط عملیاتی استفاده نکنید.

## تنظیم هوش مصنوعی

برای چت آزاد و تحلیل‌های نیازمند مدل، مقادیر زیر را در `.env` قرار دهید:

```dotenv
AI_API_KEY=your-api-key
AI_BASE_URL=https://api.openai.com/v1
AI_MODEL=gpt-4o-mini
```

`AI_BASE_URL` و `AI_MODEL` را می‌توان متناسب با سرویس سازگار تغییر داد. بدون کلید، محاسبه‌های محلی پرسش‌های آماده همچنان قابل استفاده‌اند. تنظیمات AI از طریق `config/services.php` خوانده می‌شوند و با cache تنظیمات لاراول سازگارند. کلید واقعی را در مخزن قرار ندهید.

## دریافت و تطبیق گزارش‌ها

بعد از ورود به پنل، به صفحه «گزارش‌های کمیسیون» (`/admin/commission-reports`) بروید و گزینه «همگام‌سازی صرافی‌ها» را انتخاب کنید. سه صرافی نمونه از طریق seeder ساخته می‌شوند:

در این نسخه، ایجاد، ویرایش و حذف صرافی‌ها و گزارش‌های کمیسیون از پنل غیرفعال است. صرافی‌ها با seeder و گزارش‌ها از طریق همگام‌سازی یا ورود اکسل ثبت می‌شوند.

- **LBank و Orbit:** روش دریافت آن‌ها در سیستم API است، اما چون وب‌سرویس واقعی در دسترس نبود، مولد داده، پاسخ‌های آزمایشی با قالب متفاوت برای هر صرافی می‌سازد. Provider هر صرافی داده را به adapter همان صرافی می‌دهد؛ adapter آن را به قالب مشترک سیستم تبدیل می‌کند و گزارش‌ها ذخیره و تطبیق داده می‌شوند.
- **Bitunix:** روش دریافت آن اکسل است. از لینک ساخت اکسل تستی در فرم، تعداد کاربران و گزارش‌ها و بازه تاریخ را انتخاب و فایل نمونه را دریافت کنید. سپس آن را بارگذاری کنید؛ سیستم هدرها را بررسی می‌کند و پس از تبدیل داده‌ها به قالب مشترک، گزارش‌ها را ذخیره و تطبیق می‌دهد. هدرهای مورد انتظار به‌ترتیب `uid`، `trade_volume`، `commission` و `date` هستند.

اکسل نمونه صرفاً برای شبیه‌سازی فایل دریافتی از صرافی ساخته شده است. اتصال واقعی به API یا تضمین سازگاری با فایل واقعی صرافی در این نسخه وجود ندارد.

## فیلتر و خروجی اکسل

در جدول گزارش‌ها می‌توان صرافی، وضعیت، بازه تاریخ و چند UID را فیلتر کرد؛ UIDها را می‌توان با کاما از هم جدا کرد. گزینه «خروجی اکسل» داده‌های فیلترشده جدول را در دو حالت «گزارش کامل» و «گزارش تجمیعی کاربران» دریافت می‌کند. در گزارش تجمیعی، اطلاعات بر اساس UID و صرافی گروه‌بندی می‌شوند. افزودن سطر جمع کل نیز اختیاری است.

## دستیار تحلیل گزارش‌ها

پایین صفحه گزارش‌ها، چهار سؤال آماده و امکان نوشتن سؤال آزاد قرار دارد. خلاصه کمیسیون و آمار حساب‌های صرافی محلی محاسبه می‌شوند و نیازی به کلید AI ندارند؛ دو تحلیل آماده دیگر و پرسش آزاد به سرویس هوش مصنوعی نیاز دارند. ابزارهای تعریف‌شده به مدل اجازه پرس‌وجو در محدوده داده‌های قابل پشتیبانی برنامه را می‌دهند؛ سیستم سرور مستقل MCP نیست.

در چت آزاد، تعریف ابزارهای تحلیل همراه سؤال به مدل ارسال می‌شود. مدل با قابلیت **Function Calling** و تنظیم `tool_choice: auto` در صورت نیاز ابزار و پارامترهای آن را انتخاب می‌کند. برنامه ابزار انتخاب‌شده را اجرا می‌کند و نتیجه را برای ساخت پاسخ نهایی به مدل برمی‌گرداند؛ مدل مستقیماً به پایگاه داده متصل نمی‌شود.

در سؤال‌های آماده، ابزار موردنیاز از قبل در برنامه تعیین شده و مستقیماً اجرا می‌شود. نتیجه دو سؤال به‌صورت محلی قالب‌بندی می‌شود و برای دو سؤال تحلیلی دیگر، داده‌های استخراج‌شده به مدل ارسال می‌شوند. این پیاده‌سازی از ابزارهای داخلی لاراول استفاده می‌کند و پروتکل MCP را پیاده‌سازی نمی‌کند.

با گزینه کنار ورودی چت می‌توان بین «همه داده‌ها» و «فیلترهای جدول» انتخاب کرد. در حالت فیلتر، فیلترهای فعلی جدول به درخواست تحلیل اعمال می‌شوند. گفت‌وگو فعلاً حافظه و تاریخچه پایدار ندارد و با تازه‌سازی صفحه پیام‌ها پاک می‌شوند.

## ساختار اصلی

- `app/Services/Exchanges`: قراردادها، dispatcher، providerها، adapterها و ذخیره‌سازی گزارش.
- `app/Services/FakeExchangePayloadGenerator.php`: تولید داده‌های آزمایشی صرافی‌ها.
- `app/Services/Ai`: پرسش‌های آماده، فیلترها، ابزارهای جست‌وجو و ارتباط با مدل.
- `app/Filament/Resources`: صفحات مدیریت و گزارش‌ها.
- `database/migrations` و `database/seeders`: ساختار پایگاه داده و داده‌های پایه و آزمایشی.

## اجرای تست‌ها

تست‌های کوتاه پروژه، تطبیق گزارش و محصول، جلوگیری از ثبت مجدد گزارش یکسان، فیلترهای چت و احراز هویت را بررسی می‌کنند. تست‌ها فقط از پایگاه داده موقت SQLite در حافظه استفاده می‌کنند و به داده‌های MySQL پروژه دست نمی‌زنند.

پس از ساخت یا بازسازی ایمیج Docker با Dockerfile فعلی و نصب وابستگی‌های توسعه، دستور زیر را اجرا کنید:

```bash
docker compose exec app php artisan test
```

اگر تنظیمات لاراول cache شده باشند، برای اجرای تست‌ها ابتدا cache تنظیمات را پاک کنید. تست‌ها پیش از migration بررسی می‌کنند که اتصال واقعاً به پایگاه داده موقت در حافظه اشاره کند.
